# System Patterns

## How This System Works

A directory at the repository root is one model and one release-please package. The directory name, the `component` in `release-please-config.json`, and the key in `.release-please-manifest.json` are the same string.

`publish.yaml` in that directory is the only per-model publish record. Tooling that uploads to Cults reads it for the listing text and the printable file list. The listing photos are the files in that model's `img/` directory. `images` may stay empty; it is not a second copy of that folder. The fields are the name, the description, `manufacturing`, `tags`, `license_code`, `category_id`, `subcategory_ids`, the `files` list, `images`, and `cults_creation_id`. A blank `license_code` or `category_id` means the model is not ready to publish. A blank `cults_creation_id` means Cults has not returned an id yet. `manufacturing` and `tags` may stay empty. Shared listing text and `made_with_ai` live in `author.yaml`, not in the model record.

Release-please does not discover `publish.yaml`. A model is onboarded when `publish.yaml` exists and the directory is registered in both release-please files. Conventional commits whose paths fall inside the directory drive that package. The package version is `MAJOR.MINOR.PATCH`. A `docs` commit is a patch: the printable files are unchanged and the listing changed. A `fix` commit is also a patch. A `feat` commit is a minor: the model changed and old prints still do the job the previous listing promised. A breaking change is a major: the part no longer fits what the previous version fit. A `docs` commit on a package that has never been released proposes `1.0.0`, not a patch. `author.yaml` is outside every package, so a commit that touches only that file bumps nothing. `separate-pull-requests` gives each package its own release pull request. Every release pull request still edits the shared `.release-please-manifest.json`, so `always-update` must stay true: after one release merges, release-please must rewrite the other open release branches from `main`, not only when release notes change.

The root `memory-bank/` describes the catalog. Each model directory has its own `memory-bank/` describing that model. An agent working on a model reads the model's files. An agent changing publish or release behavior reads the root files.

## Adding a model

Create the directory, its memory bank, and `publish.yaml`. Register it in `release-please-config.json` with `release-type` `simple`, `include-component-in-tag` true, and the shared pull-request header. Register it in `.release-please-manifest.json` at `0.0.0`.

Cutting a release and publishing that release are different workflows. Release-please opens the release pull request and, when that pull request is merged, creates the tag and the GitHub release. Publishing the GitHub release starts deploy for that tag. Run workflow remains for an older tag. A manual run is started from the branch that contains the current publisher. The tag input selects the model files, and the publisher is the one from that branch. It gives Cults public GitHub URLs for the printable files and the photos. A later publish updates the listing text first. Files from the tag are added, and the previous blueprint and illustration files are removed, only after that update succeeds. Cults rebuilds the public gallery only when a field on the creation changes, which those asset adds and deletes do not do. After the old files are gone, and after each STL from the tag has a preview image, the publish changes details and restores it so the gallery matches that final set. A file uploaded on Cults by hand is removed with that previous set. Every listing is free, and every create and update sends `downloadPrice` 0 together with `licenseCode`. Cults fails an update that has no price, and it resets the license to its default when a price arrives without one. Printable files use raw.githubusercontent.com. A path whose extension `.gitattributes` marks as Git LFS uses media.githubusercontent.com. After Cults returns an id, deploy writes `cults_creation_id` back to `main` in a `chore` commit that changes only that field.
